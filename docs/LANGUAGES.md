# Languages

Language here is **data, not translation infrastructure**. There is no
i18n framework; the UI chrome stays English (deliberately — it's what
keeps the app simple for mixed-generation families), while everything
culturally load-bearing comes from a *language pack*:

- the kinship vocabulary the badge engine speaks;
- lunar-calendar display names (month spellings, Suddha/Bahula vs
  Shukla/Krishna, tithi names);
- nakshatra and gotra spellings, and even the field labels
  ("Gotram" vs "Gotra");
- the native-script name fields in the edit forms, and which script
  font renders them.

Pick a pack in [app/src/family.config.ts](../app/src/family.config.ts):

```ts
language: 'telugu',   // or 'kannada' or 'english'
```

## How the kinship engine and packs divide the work

The engine ([app/src/lib/kinship.ts](../app/src/lib/kinship.ts))
computes the *shape* of every relationship — generation offset,
paternal/maternal side, cross vs parallel line, elder/younger — using
the classificatory Dravidian rules shared by Telugu and Kannada. The
pack ([app/src/lib/lang/](../app/src/lib/lang/)) supplies only the
words, as ~60 named slots (`fatherElderBrother`, `crossNephew`,
`spouseSisterYounger`, …).

Two consequences worth understanding:

- **The English gloss is generated by the engine**, not the pack, so it
  is identical and precise in every language: "father's elder brother",
  "elder brother's son". With the `english` pack the badge shows this
  gloss alone.
- **Structural differences between languages live in the slots.**
  Where Kannada splits a term Telugu merges (male cross cousins are
  ಭಾವ/ಮೈದುನ by seniority, but బావ either way in Telugu), the schema has
  two slots and Telugu simply fills both with the same word. Where
  Kannada merges what Telugu splits (one ಅಜ್ಜಿ for both grandmothers,
  vs అమ్మమ్మ/నాయనమ్మ), the Kannada pack fills both slots with ಅಜ್ಜಿ
  and the gloss keeps the side.

## The shipped packs

**Telugu** ([telugu.ts](../app/src/lib/lang/telugu.ts)) — the original.
Telugu-convention calendar (Chaitram, Suddha/Bahula, Padyami…),
Telugu-style nakshatra names (Pushyami, Pubba, Chitta), gotram/
nakshatram labels.

**Kannada** ([kannada.ts](../app/src/lib/lang/kannada.ts)) — built from
dictionary-verified research (Alar, Kannada Wikipedia, panchanga
sources) with the structural adaptations Kannada usage expects:

- ಸೋದರಮಾವ / ಸೋದರತ್ತೆ for the blood uncle/aunt (bare ಮಾವ/ಅತ್ತೆ read
  in-law-first in Kannada, and are used for the spouse's parents);
- ಭಾವ/ಮೈದುನ and ಅತ್ತಿಗೆ/ನಾದಿನಿ by seniority across cousins, siblings'
  spouses, and spouse's siblings;
- ಮಲತಂದೆ/ಮಲತಾಯಿ for step-parents (Kannada ಸವತಿ means *co-wife* — a
  false friend of Telugu సవతి);
- Kannada calendar names (Chaitra, Shuddha/Bahula, Padya, Bidige,
  Hunnime…) and nakshatra spellings (Pubba ಪುಬ್ಬಾ, Uttara ಉತ್ತರೆ…).

A few choices are house-style rather than right/wrong — ಅಜ್ಜ vs ತಾತ for
grandfather, ಆಶ್ಲೇಷಾ vs ಆಶ್ಲೇಷ — so **have a native speaker skim the
pack before launch**; it's one readable file, and correcting a word is
a one-line edit.

**English** ([english.ts](../app/src/lib/lang/english.ts)) — no native
script anywhere: badges show the precise gloss alone, edit forms drop
the native-name fields, and calendar/tradition fields stay available
with standard Sanskrit transliterations (leave them empty and they
never render).

## Adding a language

One new file plus one registry line — an AI assistant can do the whole
thing from [prompts/add-a-language.md](../prompts/add-a-language.md).
By hand:

1. Copy [telugu.ts](../app/src/lib/lang/telugu.ts) to
   `app/src/lib/lang/<language>.ts` and fill every slot (the schema
   with commentary is [types.ts](../app/src/lib/lang/types.ts)).
2. Register it in [index.ts](../app/src/lib/lang/index.ts).
3. Wire the script's font: add a `@fontsource` package to
   `app/package.json`, import it in
   [app/src/index.css](../app/src/index.css), extend the
   `--font-native` stacks and the `:lang(te), :lang(kn)` selector with
   your language tag. (Fonts load lazily — declaring several costs
   nothing at runtime.)
4. Add a few pack tests alongside the Kannada ones in
   [app/tests/kinship.test.ts](../app/tests/kinship.test.ts) and run
   `npm run test:unit` — the kinship engine needs no emulator, so this
   needs no Java. (`npm test` runs everything, rules included.)

For a non-Dravidian language, note the engine still computes
elder/younger, cross/parallel, and side distinctions — for languages
that don't mark some of those, fill the split slots with the same word
(exactly how Telugu handles slots Kannada splits).
